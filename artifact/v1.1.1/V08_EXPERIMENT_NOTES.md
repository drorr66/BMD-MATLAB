# v0.8 Experiment Notes — Cold Threshold Calibration

## Why v0.8 exists

v0.7 held both operands fixed at 256 terms and 8 BMD nodes and showed that cold BMD multiplication changed from a clear sparse loss to a robust BMD win when the operation-created workspace fell from 38 new nodes to 8 new nodes.

The purpose of v0.8 is not to introduce another polynomial family. It is to **densely calibrate that exact crossover bracket**.

## Fixed input workload

Every v0.8 case has:

- P: 256 explicit terms
- Q: 256 explicit terms
- P: exactly 8 BMD nodes
- Q: exactly 8 BMD nodes
- compact union of the two operands: exactly 16 BMD nodes
- sparse pair-products: exactly 65,536

P is the indicator support generated by exponent bits `0..7`, i.e. exponents `0..255`.

Q always has eight independent exponent bits. Seven high bits are fixed at `9..15`. The eighth bit is either fully disjoint (`16`) or overlaps one P bit (`7,6,...,0`). This changes operation closure while preserving the input cardinalities and BMD operand sizes.

## Exact structural calibration grid

Independent exact-integer reference validation gives:

| target new nodes | overlapping Q bit | Q bit set | result BMD nodes |
|---:|---:|---|---:|
| 8 | none | 9..16 | 16 |
| 12 | 7 | 7, 9..15 | 16 |
| 16 | 6 | 6, 9..15 | 17 |
| 20 | 5 | 5, 9..15 | 18 |
| 24 | 4 | 4, 9..15 | 19 |
| 28 | 3 | 3, 9..15 | 20 |
| 32 | 2 | 2, 9..15 | 21 |
| 36 | 1 | 1, 9..15 | 22 |
| 40 | 0 | 0, 9..15 | 23 |

Thus v0.8 directly samples new-node counts `8,12,16,20,24,28,32,36,40` instead of interpolating across the large v0.7 gap.

## Timing protocol

- 17 independent trials per case.
- Operand construction and compaction are outside the timed region.
- Every BMD timing starts from a freshly compacted manager containing only the two operands; computed caches are therefore empty.
- Sparse inputs are already materialized before timing.
- Measurement order alternates BMD-first / sparse-first.
- Ratio = `sparse_time / BMD_time`; values above 1 mean BMD is faster.

Conservative winner rule:

- robust BMD win: `sparse Q25 / BMD Q75 > 1`
- robust sparse win: `sparse Q75 / BMD Q25 < 1`
- otherwise: `OVERLAP`

## Primary outputs

The summary reports:

- empirical median crossover bracket in new-node units
- robust crossover bracket in new-node units
- interpolated crossover estimate (descriptive, not a theorem)
- pair-products per new BMD node on both sides of the crossover
- log correlation between BMD time and new-node count
- log correlation between BMD speed ratio and pair-products/new-node
- log-log BMD timing exponent vs new nodes
- simple linear BMD timing fit and a secondary predicted crossover

## Correctness / structural guards

Every measured case must satisfy the exact prevalidated new-node and result-node counts. The first cold BMD product is expanded after timing and compared coefficient-for-coefficient with the sparse product. Any structural drift or arithmetic mismatch marks the row as an error.

See `validation/reference_validation_v08.out`.

## Interpretation limit

A threshold from v0.8 is a calibration for this controlled fixed-input family and this MATLAB implementation. It is **not yet a universal selector**. The intended next stage is to test whether a cheap pre-operation predictor can estimate closure and whether the threshold transfers across multiple polynomial families.
